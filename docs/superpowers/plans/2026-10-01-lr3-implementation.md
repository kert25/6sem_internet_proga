# ЛР3 JavaScript Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Выполнить ЛР №11 для варианта 9, подготовив четыре интерактивных JavaScript-страницы и полный комплект материалов для сдачи.

**Architecture:** Каждое индивидуальное задание находится в самостоятельном HTML-файле в `ЛР3/` и содержит стили, элементы формы и изолированную JavaScript-логику. Результат вычислений показывается в DOM без перезагрузки. Отчёт ссылается на исходники и снимки из той же папки.

**Tech Stack:** HTML5, CSS, vanilla JavaScript, Node/CDP для браузерной проверки, Python DOCX-сборщик, Microsoft Word COM для PDF.

**Spec:** `docs/superpowers/specs/2026-10-01-lr3-design.md`

## Global Constraints

- Размещать все артефакты ЛР в `ЛР3/`; скриншоты — в `ЛР3/screenshots/`.
- Для варианта 9 выполнить задания №9, №29, №27 и №7.
- Добавлять содержательные комментарии к JavaScript-коду.
- Не использовать внешние сетевые ресурсы; изображение задания №7 должно быть самодостаточным.
- Итоговые файлы отчёта: `ЛР3/Отчет_ЛР3.docx`, `ЛР3/Отчет_ЛР3.pdf`, `ЛР3/text.docx`.

## Review Focus

- Високосный февраль: календарь за февраль 2028 должен содержать 29 дней.
- Невалидные месяц и год: календарь должен показать сообщение вместо неполной таблицы.
- Равные числа в задании №29: нестрого возрастающая последовательность должна заменить все значения максимумом.
- Числа 11–14 и отрицательное значение в задании №27: корректная форма «грибов» либо сообщение о недопустимом вводе.
- Десять изображений в задании №7: DOM должен содержать ровно десять `img` с альтернативным текстом.

### Task 1: Календарь одного месяца (задание №9)

**Files:**
- Create: `ЛР3/Ex9.html`
- Test: браузерная проверка страницы через CDP

**Interfaces:**
- Consumes: значения `year` и `month` из числовых полей.
- Produces: таблицу в контейнере `#calendar-result` и сообщение в `#calendar-error`.

- [ ] **Step 1: Создать проверку ожидаемой разметки календаря**

Открыть `Ex9.html` через CDP, установить год `2028` и месяц `2`, вызвать построение и проверить наличие 29 ячеек дней; повторить для месяца `13` и проверить видимое сообщение об ошибке.

- [ ] **Step 2: Реализовать `renderCalendar() -> void` в `ЛР3/Ex9.html`**

Функция читает поля `#year` и `#month`, валидирует целые год от 1 и месяц 1–12, а затем циклами формирует заголовок дней недели и сетку календаря. Количество дней получает через `new Date(year, month, 0).getDate()`, день недели — через `new Date(year, month - 1, 1).getDay()`.

- [ ] **Step 3: Выполнить проверку календаря**

Run: CDP-проверка из шага 1.
Expected: февраль 2028 содержит 29 дней; некорректный месяц не строит таблицу и выводит сообщение.

### Task 2: Преобразование четырёх чисел (задание №29)

**Files:**
- Create: `ЛР3/Ex29.html`
- Test: браузерная проверка страницы через CDP

**Interfaces:**
- Consumes: действительные `a`, `b`, `c`, `d` из полей с идентификаторами `#a`, `#b`, `#c`, `#d`.
- Produces: строку результата в `#result`.

- [ ] **Step 1: Создать проверку трёх ветвей условия**

Через DOM присвоить полям наборы `[1, 2, 2, 4]`, `[4, 3, 2, 1]` и `[1, 4, 2, 3]`; после запуска проверять соответственно `[4, 4, 4, 4]`, неизменённый набор и `[1, 16, 4, 9]`.

- [ ] **Step 2: Реализовать `transformValues() -> void` в `ЛР3/Ex29.html`**

Функция разбирает четыре конечных числа. Для `a <= b <= c <= d` заменяет набор его максимумом; для `a > b > c > d` сохраняет значения; в остальных случаях заменяет каждый элемент квадратом. Некорректный ввод выводит сообщение.

- [ ] **Step 3: Выполнить проверку преобразования**

Run: CDP-проверка из шага 1.
Expected: все три ветви условия выводят значения, указанные в задании.
